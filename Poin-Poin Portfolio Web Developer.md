# Poin-Poin Portfolio Web Developer

Panduan isi portfolio untuk web developer, diurutkan dari yang paling berpengaruh bagi recruiter.

## 1. Hero / perkenalan singkat

- Nama, peran yang jelas ("Fullstack Web Developer"), dan satu kalimat nilai: apa yang kamu bangun dan untuk siapa.
- CTA utama yang jelas: *Lihat proyek* dan *Hubungi saya*.
- Hindari kalimat generik seperti "passionate developer".

## 2. Proyek unggulan (inti portfolio)

Pilih 3-5 proyek terbaik, bukan semua proyek. Tiap proyek idealnya berformat **case study**:

- **Masalah**: siapa penggunanya dan apa yang perlu diselesaikan.
- **Peran kamu**: apa yang kamu kerjakan sendiri, terutama untuk proyek tim.
- **Tech stack**: Laravel, React, MySQL, dan sebagainya, plus alasan memilihnya.
- **Fitur/tantangan teknis utama**: misalnya auth dan role, validasi data, offline-first, atau manajemen stok.
- **Hasil**: dampak nyata atau angka, misalnya "mengurangi input manual", "dipakai X pengguna", atau "waktu load turun".
- **Link**: demo live, repo GitHub, dan 3-5 screenshot atau GIF singkat.

Proyek dengan klien atau pengguna nyata lebih meyakinkan daripada proyek tutorial. Kalau ada proyek yang berisi data atau sistem internal perusahaan, cek dulu apakah boleh ditampilkan, lalu samarkan data sensitifnya atau tampilkan hanya arsitektur dan fiturnya.

## 3. Skill dan tech stack

- Kelompokkan: Frontend, Backend, Database, Tools/DevOps.
- Cantumkan yang benar-benar kamu pakai di proyek, bukan daftar panjang logo teknologi.
- Tunjukkan konteks, misalnya "Laravel, dipakai di proyek A dan B".

## 4. Tentang saya

- Singkat, 2-3 paragraf: latar belakang (kuliah, pelatihan, kerja praktik), cara kerja, dan minat.
- Foto profesional membantu membangun kepercayaan.

## 5. Pengalaman dan pendidikan

- Magang/kerja praktik, proyek klien, bootcamp atau program seperti Coding Camp, dan sertifikasi (termasuk sertifikasi kompetensi).
- Tulis kontribusi konkret, bukan hanya nama institusi.

## 6. Bukti kualitas kode

- Link GitHub dengan repo yang rapi: README jelas, cara instalasi, screenshot, dan commit message yang teratur.
- Pin repo terbaik di profil GitHub.
- Poin tambahan: testing (misalnya PHPUnit), dokumentasi API, atau PRD/dokumen desain.

## 7. Kontak dan link profesional

- Email, LinkedIn, GitHub, dan opsional CV (PDF) yang bisa diunduh.
- Form kontak sederhana atau tombol email langsung.
- Status ketersediaan, misalnya "Open for freelance / internship".

## 8. Kualitas portfolio itu sendiri

Portfolio web developer dinilai dari webnya sendiri:

- **Responsif** di mobile, tablet, dan desktop.
- **Cepat**: gambar dioptimasi, skor Lighthouse bagus.
- **Aksesibel**: kontras warna cukup, navigasi keyboard, alt text.
- **SEO dasar**: title, meta description, dan Open Graph supaya link tampil rapi saat dibagikan.
- Desain konsisten dan sederhana. Kalau memakai referensi gaya seperti design.md, kuncinya adalah konsistensi token (warna, tipografi, spacing).

## 9. Opsional tapi menambah nilai

- Blog atau catatan teknis singkat tentang hal yang kamu pelajari.
- Testimoni dari dosen, klien, atau rekan tim.
- Halaman "Layanan" kalau kamu menerima freelance (jenis proyek, alur kerja, estimasi).

## Kesalahan yang sering terjadi

- Terlalu banyak proyek dengan kualitas rata-rata.
- Link demo mati atau repo tanpa README.
- Tidak menjelaskan peran sendiri di proyek tim.
- Hanya screenshot tanpa konteks masalah dan hasil.
- Halaman berat dan tidak responsif.
